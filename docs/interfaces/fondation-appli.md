## Reste à faire / fragile

- Rien n'a été essayé sur un vrai téléphone, ni dans Expo Go, ni avec une build EAS : seuls le web, la vérification de types et les tests ont tourné. Le capteur de lumière, le verrou de l'orientation, l'écran de démarrage natif et le stockage sûr n'ont donc pas été vus en vrai.
- expo-doctor : 18 vérifications sur 20 passent. Les 2 autres ont besoin d'exp.host et de React Native Directory, injoignables d'ici : à relancer avec le réseau.
- pnpm en installation isolée (pas de node-linker=hoisted) : l'export web marche et Expo le permet depuis le SDK 54, mais une première build EAS Android et iOS doit le confirmer.
- src/api/types.ts est provisoire. L'intégration doit le remplacer par @kwatt/protocol : codes d'erreur, AuthResponse, enveloppes WebSocket. Il faut vérifier les codes de fermeture WebSocket 4401 et 4403 (jeton refusé) avec la fondation serveur.
- La session de démonstration (startDemoSession, bouton visible seulement en développement sur Bienvenue) est à retirer quand l'équipe Comptes branche la vraie connexion.
- Les écrans provisoires sont à remplacer par les équipes propriétaires listées dans ROUTES.md. Pour Paramètres (13) et Plein soleil (17), les réglages de l'appareil sont déjà branchés ; il reste le compte, l'export, la suppression et l'aperçu du damier.
- L'export web, `smoke:web` et `screenshots` ne sont pas dans la CI (.github/workflows/ci.yml est partagé et n'a pas été modifié). Les ajouter à l'étape d'intégration ; les captures prennent environ 6 min.
- Le contrôleur de partie (SPEC §9) et les écrans de jeu ne font pas partie de cette mission.
- Le format du code d'ami (kwatt://ami/CODE) reste à fixer par l'équipe Communauté : il est transmis tel quel.

## Décisions

- Pas de .npmrc node-linker=hoisted : l'export web et Metro fonctionnent avec les dépendances isolées de pnpm (Expo l'accepte depuis le SDK 54). On évite ainsi de toucher l'installation des autres paquets.
- Clés de traduction typées (CustomTypeOptions) : on écrit useTranslation('<ns>') et des clés sans préfixe. Pour une clé calculée (code d'erreur, clé de route), on passe par translator, useDynamicT() ou translateError() ; le test de parité garde ces clés alignées.
- Après une connexion, l'écran d'entrée appelle setAfterSignIn(chemin) au lieu de naviguer lui-même, pour éviter qu'il navigue en même temps que la garde. La garde prend ensuite cette destination, sinon ?next, sinon l'accueil.
- « Mot de passe oublié » et « Rejoindre » restent ouverts à tout le monde, profil compris (changer son mot de passe depuis Paramètres, entrer un code). Bienvenue, Inscription, Âge et Connexion sont réservés aux joueurs sans profil, invités compris, pour qu'un invité puisse créer son profil.
- kwatt://ligue/CODE ouvre /ligue/CODE (Championnat, écran 29) : le code d'invitation sert d'identifiant. La redirection vers une coupe (30) revient à l'équipe Ligues.
- Les bandes de tissu d'espace s'affichent sur les écrans Dames (bois) et Ludo (kaba). Les écrans du hub n'en ont pas, comme les planches Accueil et Paramètres.
- /kit (catalogue du kit) est visible en développement ou avec EXPO_PUBLIC_SHOW_KIT=1 ; en production, il renvoie à l'accueil.
- Les vérifications web exportent avec l'API pointée sur le serveur local (port 8102, /v1/* répond 503) : aucune requête ne part vers un vrai serveur, pas même celui de l'autre équipe.
- Jouabilité réseau : on garde NetInfo par défaut (accès à Internet), pas l'accès au serveur Kwatt, pour ne pas montrer « Pas de réseau » quand le serveur de développement est arrêté.
- Le RankBadge déduit l'échelon du niveau (rankForLevel, SPEC §7) quand le serveur ne le donne pas ; il faudra s'aligner sur @kwatt/domain à l'intégration.
- Plein soleil : onAction passe à #0F1230 au lieu de #FBF6EA, qui ne donnait que 3,2:1 sur l'ambre (4,5:1 exigé). Les autres compléments reprennent des valeurs déjà présentes dans la palette.
